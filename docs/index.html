🔑 Hitag for Flipper Zero

A reverse-engineering project that reads, sniffs and — for the first time on a Flipper — emulates Hitag2 and Hitag S (125 kHz LF) transponders, including password and crypto modes. A proof of concept, not a polished product: it works, but it is fiddly, coupling-sensitive, and needs a patched firmware. For tags and readers you own.

Source & write-up ⬇ Download .fap 📖 Reference
⚗️ This is an experiment, not a product. It came out of reverse-engineering how the Flipper's 125 kHz front end can be made to emulate a Hitag2 tag — something no mainline firmware does. It has genuinely worked against real readers, but success depends on marginal analog coupling and on a firmware patch you must flash yourself. Expect to tinker. Read the limitations before you rely on it for anything.

The research

No mainline Flipper firmware (official, Momentum, Unleashed, RogueMaster) supports Hitag2 read or emulate. The only public prior art is the unmerged Hitag1 / reader-talks-first (RTF) pull request flipperzero-firmware #2658. This project extends that base to Hitag2 (password + crypto), a full Hitag S implementation, and — most interestingly — tag emulation that drives the coil's load modulation to answer a real reader.

The framing discovery

The reader strips a fixed-length start-of-frame, then reads the rest as data. Matching the preamble to that length and sending the raw 32 bits (dropping an earlier leadbit hack that lost bit 31, e.g. 0xAA → 0x2A) makes every page read back faithfully — the key that unlocked crypto reads too.

Timing, not luck

Emulation only works if the reply lands inside the strict Hitag2 window. An in-app autotune sweeps the reply delay and locks on the first timing that completes — repeatable across readers.

Validated on a Proxmark3

Every step was cross-checked with a Proxmark3 as the reference reader (lf hitag read --ht2), which reads the emulated tag back exactly — the ground truth behind the claims here.

It's LF, not NFC

Hitag2 is 125 kHz — nothing to do with the Flipper's 13.56 MHz NFC chip. It all runs on the STM32WB: a timer makes the carrier, the analog comparator demodulates, a pull‑out pin does the load modulation.

What it does

Read & Sniff

Read a Hitag2 password-mode tag (UID, password, 8 pages), or passively sniff a real reader: recover its password, collect Hitag2 crypto nonces for a PC cracker, or capture a Hitag S 82xx password. Save/load .hitag dumps.

Emulate Hitag2

Play a dump back to a reader with a live AUTH / PWD / RD readout. Password mode (Normal / Tolerant, Auto-timing) and a separate crypto mode — full nRaR mutual auth with the 48-bit cipher, then encrypted reads.

Emulate Hitag S

A complete Hitag S tag: UID_REQ → SELECT → READ / WRITE across all four reader modes, plus crypto/challenge, 8268/8310 password, and enforced config lock bits.

Detect & keys

Detect auto-rotates Hitag2 / Hitag1 / Hitag S. Edit the Hitag2 password, the Hitag S crypto key and the 82xx password from the menu. Diagnostic traces are off by default, behind a debug toggle.

Basic Hitag1

A Read Hitag1 mode is carried over from the RTF base — but no Hitag1 tag was on hand to test it, so treat V1 as untested (see limitations).

Limitations & caveats

  • Not a drop-in FAP. It needs a firmware HAL that the stock SDK lacks, so you must build and flash a patched firmware — not just copy a .fap.
  • Coupling is marginal and position-sensitive. LF emulation depends on analog load modulation; a few millimetres change everything. On some readers it completes readily, on others only in a narrow sweet spot — and it may not couple at all. When nothing comes through, slowly move the tag — or the Flipper — relative to each other, a millimetre at a time, until it couples; finding the sweet spot is a physical hunt, not a setting.
  • Readers vary. A strict reader can reject a reply that a Proxmark3 accepts. The Tolerant and Auto-timing modes exist precisely because there is no single setting that works everywhere.
  • Emulation-first. The Hitag S and Hitag2-crypto work is validated as a tag against a reader (Proxmark3). Reading a Hitag S as the reader implements UID + SELECT only; the full page loop is coupling-limited.
  • Hitag1 barely covered. No Hitag1 tag was available during development, so Hitag1 could not be exercised: Read Hitag1 is wired but untested, and a Hitag1 sniff is not provided.
  • Proof of concept. Validated on a Proxmark3 and a handful of real readers — not broadly tested. No guarantee it works with your specific hardware.
  • Diagnostics are opt-in. Timing/handshake logs are off by default; a Debug traces toggle writes them to the SD card when you want to debug a reader.

Install

Two parts. Hitag2 LF emulation needs a small firmware HAL that the stock SDK lacks, so unlike a normal FAP you must also flash a patched firmware. The .fap alone will not run.

  1. Firmware. Apply firmware/rtf-hal.patch to a Momentum tree, then build & flash it (./fbt flash_usb). The patch is additive (an RTF HAL) and self-contained.
  2. App. Build the FAP against that patched SDK, or grab the prebuilt .fap from the latest release.
  3. Copy the .fap into SD Card / apps / RFID (or install with qFlipper).
  4. On the Flipper: Apps → RFID → Hitag.
  5. Lay the tag (or the reader) against the bottom/USB-C end of the Flipper, where the 125 kHz coil is, and pick an action. Coupling is position-sensitive: if nothing happens, slowly move the tag or the Flipper relative to each other until it couples — when emulating, watch the live AUTH counter and keep repositioning until it climbs.

Legal & ethical use

Independent, unofficial research project, provided "as is". Use it only on transponders and readers you own or are explicitly authorized to test. Cloning or emulating access credentials you do not own may be illegal in your jurisdiction. The default password shown is the public, documented NXP factory-default value — not a secret. No manufacturer firmware, artwork or logo is included.
